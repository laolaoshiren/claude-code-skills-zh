📦 3 种部署方式（Windows / macOS / Linux / Docker）

核心逻辑分为两步：先运行登录工具保存 Cookie，再启动 xiaohongshu-mcp 服务监听 18060 端口。首次启动会自动下载约 150MB 无头浏览器。

方式 1：Windows x64 预编译二进制

零 Go 环境

从 GitHub Releases 下载 xiaohongshu-login-windows-amd64.exe 与 xiaohongshu-mcp-windows-amd64.exe（不支持 macOS Intel 与 Linux ARM64）。

Windows PowerShell 
# 1. 首次扫码保存登录态
.\xiaohongshu-login-windows-amd64.exe

# 2. 启动 MCP（建议配环境变量 AUTH_TOKEN 启用鉴权）
$env:AUTH_TOKEN = "replace-with-random-token"
.\xiaohongshu-mcp-windows-amd64.exe

方式 2：Docker Compose（无界面 / noVNC GUI）

服务器 / 隔离环境

日常自动化用无界面版；排查验证码或登录现场时可选 novnc 版（http://127.0.0.1:6080/vnc.html）。

Docker Compose 
git clone https://github.com/xpzouying/xiaohongshu-mcp.git
cd xiaohongshu-mcp
# 无界面版（默认）
docker compose -f docker/docker-compose.yml up -d
# 或：带可视化浏览器 GUI 版（仅限本机访问）
docker compose -f docker/novnc/compose.yml up -d

方式 3：Go 源码编译（配国内 GOPROXY）

支持自定义调试

遇到闪退或需要改超时、代理配置时推荐源码启动，支持 XHS_PROXY（HTTP/HTTPS/SOCKS5）。

Go 源码运行 
go env -w GOPROXY=https://goproxy.cn,direct
go run cmd/login/main.go
# 排查问题可加 -headless=false 弹出真实浏览器窗口
go run . -headless=false

步骤 4：用 MCP Inspector / curl 验证连通

上线前必测

确认 List Tools 能返回全部 13 个工具后再让 Agent 接入。

验证服务状态 
# 方式 A：可视化调试面板
npx @modelcontextprotocol/inspector

# 方式 B：命令行探活
curl -X POST http://localhost:18060/mcp -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","method":"initialize","params":{},"id":1}'

🛡️ 防踢号规则、安全部署与合法使用边界

⚠️ 小红书平台规则与防踢号硬约束（来自原仓实操总结）
  • 严禁多网页端同时登录：小红书同一账号不允许在多个网页端在线。登录 xiaohongshu-mcp 后，不要再在日常浏览器里打开小红书网页版，否则会立刻把 MCP 会话踢掉；日常看号请用手机 App。
  • 字数与实名门槛：标题严格不超过 20 个字，正文不超过 1000 个字；未实名账号（尤其新号）容易弹出实名认证提示，建议先实名后再接入检索或发文。
  • 图片与视频约束：图文发布强烈推荐使用不含中文字符的本地绝对路径（比 HTTP 图床更稳）；视频发布仅支持单个本地视频文件绝对路径（建议 ≤ 1GB）。
🚨 安全暴露红线与自动化合规边界
  • 绝不把 18060 或 noVNC 6080 暴露公网：原仓特别警告 noVNC GUI 无独立密码，必须仅限本机 127.0.0.1 或 SSH 隧道访问；远程部署 MCP 时务必通过环境变量 AUTH_TOKEN 启用 Bearer 鉴权（避免用 -token 启动参数暴露给 ps 进程列表）。
  • 保留人工确认，拒绝滥用：原仓声明项目仅供学习与个人效率辅助，禁止违法违规、恶意引流、纯搬运抄袭或高频刷评刷赞；Agent 调用 publish_content / post_comment_to_feed 前建议先设 visibility="仅自己可见" 验证或人工确认内容。
  • OpenClaw 用户注意：原仓作者明确不建议直接把仓库丢给 OpenClaw 自动部署，且 MCPorter 中间层可能带来额外兼容性问题；无强需求建议优先选用原生支持 HTTP MCP 的 Claude Code / Cursor / Cline。

❓ 常见问题 FAQ

Q1：检查登录状态时用户名显示 xiaghgngshu-mcp 是中毒了吗？

不是。原仓 FAQ 已说明当前版本该显示名在源码中是写死的占位字符串，只要能正常调用 list_feeds 与 search_feeds 即代表会话有效。

Q2：search_feeds 能直接按「最新」或「最多收藏」过滤吗？

可以。search_feeds 支持传入 filters 对象：sort_by（综合 / 最新 / 最多点赞 / 最多评论 / 最多收藏）、note_type（不限 / 视频 / 图文）、publish_time（一天内 / 一周内 / 半年内）、search_scope 与 location（同城 / 附近），非常适合做中文垂直选题调研。

Q3：想先看长评论区再决定写什么，怎么防止无限滚动卡死？

调用 get_feed_detail 时默认只取前 10 条一级评论；需要深挖痛点时再设 load_all_comments: true，并用 limit（默认 20）、reply_limit（默认 10）和 scroll_speed 控制抓取上限。

Q4：跟本库里的 baoyu-skills 或 autoclaw-cc/xiaohongshu-mcp-skills 怎么配合？

xpzouying/xiaohongshu-mcp 是底层 MCP 执行服务；你可以用 JimLiu/baoyu-skills 里的 baoyu-xhs-images 生成 12 种风格的小红书卡片图，再交由本地 xiaohongshu-mcp 或 autoclaw-cc/xiaohongshu-mcp-skills 工作流管理素材与发布预览。
