🎯 为什么 Agent 写的前端一眼就能看出“AI 味”？

不加约束时，不同模型都会反复跌进同一套保守模板。Impeccable 用三层机制把控制权还给开发者：

常见 AI 模板病（Impeccable 重点拦截）

  • 全站一律 Inter 字体、白底/暗底配千篇一律的紫蓝渐变按钮。
  • 卡片套卡片、每个标题上方都硬塞一个圆角方块图标。
  • 彩色背景上放浅灰字导致对比度不足、内边距局促或标题层级跳跃。
  • 对 Agent 喊“高级一点 / Make it pop”，结果整页被盲目重做。

Impeccable 的三层解法

  • 先立规矩：/impeccable init 生成 PRODUCT.md，document 沉淀 DESIGN.md。
  • 精确局部操刀：一次只点名一个区域配一个动词（如 /impeccable polish settings），比整页重画稳得多。
  • 本地硬拦截：Agent 编辑 Hook + CLI detect 跑 62 条确定性规则，无需大模型 Token 就能把“AI 味”挡在提交前。

🛡️ 62 条反 AI 味检测器：Hook、终端 CLI 与 GitHub Actions SARIF

检测器本身封装为独立原生引擎，零 API Key、零 Token 消耗。遇到需要看真实像素对比度或微小文字的规则，可直接指向本地开发服务器 URL：

终端扫描源码 / 本地预览 URL / 生成 SARIF 报告 
# 扫描源码目录（JSX/TSX/HTML/CSS 模式规则）
npx impeccable detect src/

# 扫描本地开发服务器（调用本机 Chrome/Edge 检测真实对比度与字号）
npx impeccable detect http://localhost:5173

# 列出全部 62 条规则 ID 与说明
npx impeccable detect --list-rules

# CI 中输出 SARIF 2.1.0（注意：退出码 2 表示发现问题，1 表示扫描失败）
npx impeccable detect --sarif src/ > impeccable.sarif || test $? -eq 2

⚠️ 安全、Live 模式与 Git 协同注意事项

🔒 使用前必须了解的 4 条安全与工程边界
  • Live 模式限本地开发环境：/impeccable live 会在本地 dev server 打开浮层并写回源码，严禁注入线上部署站点或削弱生产 CSP；其后台 Apply 回退调用会以绕过沙箱参数运行 codex/claude，建议设为 IMPECCABLE_LIVE_COPY_AGENT=chat 仅在当前对话内应用修改。
  • Hook 在模型审批之外执行：Claude Code 安装命令 Hook 后，即使拒绝模型命令，首次编辑文件仍可能触发 Hook 下载引擎二进制；审查不信任仓库前可用 --settings '{"disableAllHooks": true}' 临时关闭。
  • 关闭匿名遥测：新建设计时若不需要上传“展示了哪些方向/选了哪个方向”的匿名统计，可运行 npx impeccable telemetry off 或设置 DO_NOT_TRACK=1。
  • 精简 Git 追踪范围：提交 PRODUCT.md、DESIGN.md 与 .impeccable/config.json 等共享规范；把 **/.impeccable/*.png、review/、live/sessions/ 与 hook.cache.json 加入 .gitignore。

❓ 常见问题 FAQ

Q1：适合中文团队的 B 端后台和中文产品文案吗？

适合结构、间距、对比度、无障碍与状态完整度治理（如 audit、harden、adapt）。但原仓提示语与设计规则为英文编写，中文产品微文案（clarify）和本地字体排印习惯（如思源黑体/苹方混排）建议结合 PRODUCT.md 显式写明中文语境要求。

Q2：为什么 PRODUCT.md 比直接写长 Prompt 好用？

长 Prompt 每次换新会话就丢；/impeccable init 提问后生成的 PRODUCT.md 持久化在仓库里，所有后续 24 条指令都会先读它，确保同一项目的按钮层级、配色与目标人群始终一致。

Q3：已经有团队品牌字体（比如就用 Inter）总是被检测器报警怎么办？

运行 npx impeccable ignores add-value overused-font Inter --reason "Brand font" 即可全局豁免；单文件豁免则加注释 <!-- impeccable-disable overused-font: reason -->，并可用 --report-unused-ignores 清理过期豁免。

Q4：遇到配置损坏或 Hook 报错怎么一键诊断？

直接在 Agent 中运行 /impeccable doctor，会自动检查过期的上下文文件、无效配置以及损坏的生命周期 Hook 路径。
