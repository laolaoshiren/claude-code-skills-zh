📦 人类开发者与 AI Agent 双路径快速上手

前置条件：Node.js（npm/npx）；仅从源码编译时需 Go v1.23+ 与 Python 3。官方 README 专门区分了「人类交互式」与「AI Agent 协作式」两种初始化流程：

路径 A：npm 一键安装（个人首选）

Windows / macOS / Linux

先装 CLI，再初始化应用凭证并完成 OAuth 授权，三步跑通第一条日历查询。

PowerShell / Shell 
# 1. 全局安装 CLI（含嵌入 Skills）
npx @larksuite/cli@latest install

# 2. 交互式初始化飞书应用凭证（仅需一次）
lark-cli config init

# 3. 授权常用推荐权限并验证
lark-cli auth login --recommend
lark-cli calendar +agenda

路径 B：源码编译 + 单独装 Skills

Go v1.23+

若需二次裁剪或排查源码，构建后务必额外执行 npx skills add 装入 Skill 定义。

源码构建 
git clone https://github.com/larksuite/cli.git
cd cli
make install

# 安装全部官方 Agent Skills（必需）
npx skills add larksuite/cli -y -g

路径 C：让 AI Agent 引导用户授权

无头 / 后台协作

Agent 在后台运行命令并提取输出的授权 URL 发给用户，用户在浏览器确认后命令自动返回。

Agent 协作流 
# Agent 后台运行，输出授权链接交由用户打开
lark-cli config init --new
lark-cli auth login --recommend

# 验证当前用户/应用身份状态
lark-cli auth status

企业级接入与自省技巧

ISV / 团队自研

任意飞书开放平台文档 URL 后加 .md 即可让 Agent 直读原始 Markdown；企业定制使用仓库 extension/。

Schema 自省与文档 
# 离线自省任意 API 参数、请求体与 scopes
lark-cli schema
lark-cli schema calendar.events.instance_view
lark-cli schema im.messages.delete

⚙️ JSON 输出契约、分页控制与 Dry-Run 预览

编写自动化脚本或让 Claude Code 解析命令行返回时，以下原仓约定非常关键：

  • 判断成功看 ok == true（切勿用 code == 0）：默认 --format json 下，成功信封输出到 stdout（{"ok":true,"identity":"user","data":...}，不含 code 字段）；错误信封输出到 stderr（{"ok":false,"error":{"type":"api","code":99991679,...}}）。
  • 五种输出格式与安全分页：支持 json、pretty、table、ndjson（适合管道流式处理）与 csv；批量拉取可配合 --page-all --page-limit 5 --page-delay 500 防止触发频率限制。
  • 有副作用命令先加 --dry-run：发消息、改多维表格或创建日程前，建议让 Agent 先加 --dry-run 打印真实请求载荷给人类确认。

🛡️ 安全防护机制与使用边界

⚠️ 授权边界：私人助理优先，严禁拉入公共群聊
  • 以你的用户身份执行：完成 OAuth 授权后，Agent 拥有对应 Scopes 内的读写与发送权限。官方明确建议仅将接入机器人的终端作为私人对话助手，不要拉入多人大群，以防群成员通过消息实施提示词注入或越权套取云文档数据。
  • OS 原生密钥链与输出净化：凭证默认存储在系统原生 Keychain/Credential Manager 中，内置输入防注入与终端输出净化保护，不要随意关闭默认安全配置。
📡 最小化风控信号说明与开关命令
  • 为降低访问令牌被盗用后的风险，CLI 向飞书官方精确 HTTPS 域名发起 OpenAPI 请求时，默认附带两条最小化设备特征：操作系统类型（macOS/Windows/Linux）与设备硬件型号（如 Mac17,9）。
  • 如需在当前工作区退出或恢复该保护，可使用原生命令控制：lark-cli config risk-control off / on / default。

❓ 常见问题 FAQ

Q1：如何让 Claude Code 读取最新的飞书开放平台文档而不被网页 HTML 干扰？

飞书官方在文档中给出技巧：任意飞书开放平台文档 URL 加上 .md 后缀即可直接返回原始 Markdown（例如 embed-feishu-cli-in-agent.md），也可直接执行 lark-cli schema <method> 本地自省参数与所需权限 scopes。

Q2：跟第三方飞书 MCP（如 cso1z/Feishu-MCP）或 openclaw-china 怎么选？

如果你主要通过终端 Agent（Claude Code / Codex）操作飞书文档、多维表格、日程、审批和 OKR，首选官方维护且 MIT 开源的 larksuite/cli（能力覆盖最全、更新同步开放平台）；如果是把消息机器人接入 OpenClaw IM 渠道网关，可搭配本库收录的 openclaw-china 或 feishu-openclaw。

Q3：快捷命令和通用 lark-cli api 怎么配合？

高频操作（如发消息、查议程、创建 Markdown 文档）直接用带 + 前缀的快捷命令；需要尚未封装的冷门 OpenAPI 时，先用 lark-cli schema 查清参数，再通过 lark-cli api GET/POST /open-apis/... 直接调用，避免自己手写鉴权和签名。

Q4：企业想限制 Agent 只能读文档不能删文件、还要把 Token 存到 Vault 怎么办？

不要改 CLI 源码。官方提供了 extension/ 扩展包，支持通过 wrapper main 注入企业级中心化凭证管理、统一审计日志以及命令白名单裁剪。
