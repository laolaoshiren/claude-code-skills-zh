🧩 四平面组合与 od mcp install 命令生成器

选择你常用的编码 Agent CLI、品牌设计系统（来自 design-systems/）与目标产物模板，实时生成 MCP 安装指令与开箱即用对话提示词：

1. 选择本地编码 Agent（支持 16+ CLI）
2. 选择品牌级 DESIGN.md（节选自 151 套设计系统包）
3. 选择产出平面与设计场景
claude + linear-app + Prototype

通过 stdio MCP 直连本地 OpenDesign 项目，Agent 直接读写 tokens.css 与入口 HTML 并实时刷新预览。

🏗️ 四平面可组合架构：插件 × 技能 × 模板 × 设计系统

OpenDesign 把以往混杂在一堆 Prompt 里的设计工程拆成四个职责清晰的可版本化目录，任何团队都可以按需替换或自建私有包：

🎨 design-systems/（151 套品牌契约）

每套包以 DESIGN.md 为核心品牌契约，新包还附带 manifest.json、编译后的 tokens.css 与样例组件，覆盖 Stripe、Linear、Apple、Notion、Vercel 等主流产品语言与入门模板。

🧩 skills/（171 项功能技能目录）

严格遵循 SKILL.md 协议，为 Agent 提供行为规范与参考资料——包含 apple-hig、figma-implement-design、d3-visualization、impeccable-design-polish、web-clone（MIT）等。

🖼️ design-templates/（115+ 渲染蓝图）

覆盖网页原型（saas-landing / pm-spec）、15 套 Deck × 36 主题 Web PPT（含 guizang-ppt）、小红书卡片模板以及内置的 hyperframes HTML→MP4 动效模板。

🔌 plugins/_official/（277 官方插件）

以 open-design.json 封装完整场景包，如 od-design-refine、od-figma-migration、od-react-export、od-nextjs-export 与 od-vue-export。

📦 三种零门槛运行方式（桌面版 / Docker / 源码开发）

普通产品/研发团队无需配置 Node 24；仅需要二次开发源码或定制后台守护进程时才需要本地安装 Node ~24 与 pnpm@10.33.2：

方式 A：独立桌面应用 + MCP（推荐首选）

Windows x64 / macOS / Linux

从 GitHub Releases 下载安装包，自动探测本机编码 Agent，再用 od mcp install 暴露实时项目文件给终端 Agent。

MCP 接入与项目检查 
# 按所用编码 Agent 注入 MCP（支持 claude / codex / cursor / antigravity / trae / kimi 等）
od mcp install claude

# Agent 可按名称实时查询项目与设计文件
od project list --json
od files list <project-id> --json
od skills list --json

方式 B：Docker Compose 自托管

免 Node.js 环境

适合不想在本机装前端工具链的用户，启动后访问 http://127.0.0.1:7456；务必配置随机 OD_API_TOKEN。

Shell / Docker 
git clone https://github.com/nexu-io/open-design.git
cd open-design/deploy
cp .env.example .env
# Linux/macOS 生成随机 Token 写入 OD_API_TOKEN=
echo "OD_API_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose up -d

方式 C：源码开发模式（tools-dev）

Node ~24 + pnpm 10.33.x

官方仅支持 pnpm tools-dev 作为本地生命周期入口（已移除旧版 pnpm dev 等别名），Windows 用户可先查阅 docs/windows-troubleshooting.md。

源码启动 
git clone https://github.com/nexu-io/open-design.git
cd open-design
corepack enable
pnpm install
pnpm tools-dev run web

常用生命周期排查命令

daemon + web + desktop

当后台进程端口冲突或需要排查日志时，使用 tools-dev 自检命令。

tools-dev 诊断 
pnpm tools-dev status
pnpm tools-dev check
pnpm tools-dev restart --daemon-port 7457 --web-port 5175
pnpm tools-dev stop

🛡️ 架构安全模型与 Windows 环境注意事项

🔒 本地回环绑定、只读 MCP 与 SSRF 防护
  • 默认绑定 127.0.0.1 且 MCP 默认只读：本地守护进程不会主动暴露在局域网；若确需远程或团队共享访问，必须显式设置 OD_BIND_HOST 与 OD_ALLOWED_ORIGINS 白名单，并在反向代理层加鉴权。
  • BYOK 代理边界：支持自备 API Key（BYOK）并内置 SSRF 防护；使用云端模型或 OpenDesign Cloud 时，请求会发送至对应服务端，涉及保密商业原型建议保持纯本地运行。
⚠️ 源码运行环境与多许可证提醒
  • Windows 原生 vs WSL2：若你的 Claude Code / Codex 装在 WSL2 中，请按仓库 docs/wsl-setup.md 配置跨环境路径检测；Windows 原生源码启动先检查 Node 24 与 Corepack 下的 pnpm 10.33.2 版本。
  • 子包许可证区分：主仓为 Apache-2.0，但部分内置模板（如 guizang-ppt、html-ppt）与技能（如 web-clone）沿用各自目录内的 MIT 许可，商用二次分发时请留意对应子目录声明。

❓ 常见问题 FAQ

Q1：我和 `pbakaus/impeccable` 相比，OpenDesign 更适合哪类需求？

impeccable 专注于在已有代码工程中通过 24 条设计指令消除 AI 模板味、优化视觉细节；OpenDesign 则是一个完整的可视化设计工作台 + 设计系统仓库（151 套 DESIGN.md），除了生成原型，还能直接出 Web PPT、HyperFrames MP4 动效视频以及导出 React/Next.js/Vue 组件。

Q2：为什么仓库目录里既有 skills/ 又有 design-templates/？

skills/ 提供“怎么做”的功能性 Agent 能力（如 Figma 还原、设计走查、3D 样机、图像增强），design-templates/ 提供“长成什么样”的可渲染起点蓝图（如看板、OKR 记分卡、商业计划书 Deck）。实际工作流中把二者和 DESIGN.md 组合调用。

Q3：不装本地大模型或不想登录云端，能白嫖免费模型吗？

OpenDesign 本体开源免费，不强制购买云端额度。它直接调用你本地已认证的 claude、codex、kimi、trae 等 CLI，或者接入你自己的 BYOK 接口。只有需要云端托管协作或使用 OpenDesign Cloud 付费模型套餐时才涉及额外计费。

Q4：可以把团队自己的企业 UI 规范做进 OpenDesign 吗？

可以。按照 design-systems/README.md 规范，把包含色彩、字号、间距、组件约束的 DESIGN.md（以及可选 tokens.css）放进 design-systems/<brand>/ 目录，选择器就会自动识别你的企业设计系统。
