🏗️ 为什么纯大模型 Prompt 审查容易翻车？阿里是怎么解的？

原仓在 AACR-Bench（50 个真实开源仓库、200 个 PR、10 种语言、1,505 条人工交叉标注缺陷）中指出，纯语言驱动的通用 Agent 在大变更集下容易出现漏审文件、行号漂移与质量波动。Open Code Review 把流程拆成两层：

确定性工程层（绝不能出错的硬约束）

  • 精准文件筛选：由确定性逻辑圈定所有待审文件，防止大 PR 被模型“偷懒跳过”。
  • 智能关联分包：把强关联文件（如多语言配置或上下游模块）归为一包，以独立子 Agent 并发审查并隔离上下文。
  • 模板化规则匹配：按文件语言与特征精准注入 NPE、线程安全、XSS、SQL 注入等规则，减少无关噪声。
  • 独立定位与反思模块：专门修正评论行号与过滤低价值误报。

Agent 动态推理层（专注需要判断的部分）

  • 跨文件深层取证：不只看 diff 片段，而是按需读取完整文件、搜索调用链与其他变更文件。
  • 场景特化工具集：基于大规模生产调用轨迹精简工具链，减少重复无效工具调用。
  • 成本与精准度取舍：官方基准显示在相同底层模型下准确率（Precision）与 F1 更高、Token 消耗约降为通用 Agent 的 1/9（以低噪声换取略低召回率）。

⚖️ 最关键选型：原生模式（Native） vs 委托模式（Delegation）

很多中文开发者装完才发现「Claude Code 订阅账号不能直接当原生模式的 API Key」——提前看懂这两种模式能省掉大量配置折腾：

对比维度 原生模式（Native） 委托模式（Delegation）
对应 Skill / 命令 open-code-review / ocr review open-code-review-delegate / delegate-review
模型与认证来源 OCR 独立配置的 LLM Provider（需独立 API Key） 直接复用宿主 Agent（Claude Code / Cursor / Codex / Kimi Code）现有登录与额度
管线能力范围 跑满 OCR 完整原生审查管线、独立定位与反思模块 由 OCR CLI 提供文件筛选、规则解析与护栏，宿主 Agent 执行分析与输出
最适合谁 有独立 API Key、需要接入 GitHub Actions / GitLab CI / Gerrit 的研发团队 个人开发者提交前自检、没有独立 API Key 或不想再配一套凭据的用户

⚡ 安装与高频命令速查（Windows / macOS / Linux）

两种模式都要求本地满足 Git ≥ 2.41 且已安装 ocr CLI；原生模式才需要执行 ocr config provider：

步骤 1：全局安装 ocr CLI（npm 跨平台通用） 
git --version
npm install -g @alibaba-group/open-code-review
步骤 2：为 Claude Code / Codex / Cursor / Kimi 安装 Skills 
npx skills add alibaba/open-code-review
原生模式：交互式配置模型端点与 Key 
ocr config provider
ocr config model
日常高频审查与全目录体检命令 
# 审查当前工作区全部未提交改动
ocr review
# 审查当前分支相对 main 的改动
ocr review --from main
# 审计没有 git diff 的遗留目录（支持断点续扫）
ocr scan --path internal/agent
# 委托模式预览待审文件与规则
ocr delegate preview

⚠️ 中文开发者实测避坑与注意事项

上手前先检查这 4 点，避免卡在环境与成本问题：
  • Git 版本门槛（硬性 ≥ 2.41）：Windows 或老旧 Linux 服务器若 Git 版本偏低，ocr review 会直接失败；先用 git --version 核验。
  • 区分订阅额度与独立 API Key：Claude Code Pro/Team 登录态不会自动变成 ocr review 原生模式的 API 凭据；没单独配 Key 时请直接使用 open-code-review-delegate 委托模式。
  • 代码隐私与模型端点合规：无论哪种模式，待审源码与上下文都会发往你配置的 LLM 端点；企业内部涉密代码库请务必配置内网自托管或经公司合规审批的兼容 OpenAI/Anthropic 端点。
  • 中断可续跑：大仓库审查若因网络波动中断，可先跑 ocr session list 查回话 ID，再用 --resume <session-id> 续扫，避免重复消耗 Token。

❓ 常见问题 FAQ

支持哪些国产编码 Agent 和 CI 平台？

除 Claude Code、Codex、Cursor、OpenCode 外，官方仓库内置了 .kimi-plugin/ 专门支持 Kimi Code，CI 侧支持 GitHub Actions（根目录自带 action.yml）、GitLab CI、GitFlic CI 与 Gerrit。

没有独立模型 API Key 能先体验吗？

可以，装完 ocr CLI 与 open-code-review-delegate 技能后，即可在委托模式下借用宿主编码 Agent 现有模型运行规则筛选与审查流程。

适合跟本仓原创技能 zh-code-reviewer 怎么分工？

日常个人快速看小改动，用零依赖的 zh-code-reviewer 最轻快；团队级大 PR、需要多语言内置安全规则（NPE/并发/XSS/SQL 注入）或接入 CI 自动卡点时，优先上 alibaba/open-code-review。
