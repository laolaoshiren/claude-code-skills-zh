🎯 中文创作者选型建议：按场景拆装，别整包一把梭

原仓官方 README.zh.md 明确提醒：仓库包含 22 个技能，不要一次性全装——每个已加载的 Skill 都会在 Agent 每次对话时占用上下文窗口。建议按实际发布渠道，每次只装 2–4 个核心单项：

📱 公众号技术专栏（最小组合）

baoyu-cover-image + baoyu-article-illustrator + baoyu-post-to-wechat

省心点：不必另装 baoyu-markdown-to-html，因为 baoyu-post-to-wechat 已内置 Markdown 转公众号富文本流程；只有整理杂乱草稿时再补装 baoyu-format-markdown。

📕 小红书图文运营组合

baoyu-xhs-images + baoyu-image-gen + baoyu-compress-image

省心点：内置 12 种视觉风格（如 notion、study-notes、chalkboard、cute）与 3 套配色，支持 --yes 非交互批量出图并压缩体积。

✍️ 纯技术博客（零生图 API 成本）

baoyu-diagram + baoyu-translate + baoyu-format-markdown

省心点：baoyu-diagram 由 Claude 直接手算坐标写自包含 SVG（内置深浅色适配），无需配置任何生图模型 Key 就能产出清晰流程图、时序图与架构图。

根据 JimLiu/baoyu-skills 的 skills/ 目录与 .claude-plugin/marketplace.json 实测核验，共分为内容创作、AI 生图与效率工具三大类：

分类 技能名 核心能力与中文场景说明

内容与发布 baoyu-diagram / baoyu-infographic / baoyu-slide-deck / baoyu-comic 手写深浅色 SVG 技术图表（不耗生图 API）、信息图、逐页演示幻灯片与漫画分镜。

📦 Windows PowerShell 与 macOS/Linux 安装指南

安装前请确认本机已安装 Node.js，且终端能够正常运行 npx bun。推荐按需单装，不要整包盲装。

方式 1：通用 CLI 交互式 / 按需单装（推荐）

跨平台通用

运行首条命令可在终端勾选所需单项；或直接用 --skill 指定只装微信公众号相关技能。

npx skills（Windows / macOS / Linux 通用） 
# 交互式勾选需要的单项技能
npx skills add jimliu/baoyu-skills

# 示例：仅单装微信公众号发布与封面图
npx skills add jimliu/baoyu-skills --skill baoyu-post-to-wechat --skill baoyu-cover-image

方式 2：Claude Code 插件市场（注意整包加载）

加载全部 22 项

若确实需要频繁切换多类创作技能，可在 Claude Code 2.1+ 中注册插件市场安装完整插件包。

Claude Code Slash Command 
/plugin marketplace add JimLiu/baoyu-skills
/plugin install baoyu-skills@baoyu-skills

方式 3：Windows PowerShell 5.1+ 手动单装

Codex / Claude Code

只把需要的技能目录复制到全局 $HOME\.claude\skills\（若用于 Codex 项目级，目标改为 .\.agents\skills\）。

Windows PowerShell 
git clone https://github.com/JimLiu/baoyu-skills.git
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse -Force ".\baoyu-skills\skills\baoyu-post-to-wechat" "$HOME\.claude\skills\"
Copy-Item -Recurse -Force ".\baoyu-skills\skills\baoyu-cover-image" "$HOME\.claude\skills\"

方式 4：macOS / Linux 手动单装与项目级配置

Bash / Zsh

同样支持按单个目录拷贝，避免全量加载。多账号与自定义配色通过 .baoyu-skills/<skill-name>/EXTEND.md 扩展。

macOS / Linux Shell 
git clone https://github.com/JimLiu/baoyu-skills.git
mkdir -p ~/.claude/skills
cp -r baoyu-skills/skills/baoyu-post-to-wechat ~/.claude/skills/
cp -r baoyu-skills/skills/baoyu-cover-image ~/.claude/skills/

Windows PowerShell 代理与环境变量避坑（高频踩雷点）

原仓明确提醒：Windows PowerShell 不支持 Linux 风格的 HTTP_PROXY=http://... /skill 内联写法。需要代理访问海外模型或平台时，必须先在当前会话赋值，再在同一会话内启动 Agent：

Windows PowerShell 会话代理设置 
$env:HTTP_PROXY = 'http://127.0.0.1:7890'
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
# 在当前 PowerShell 会话启动 Claude Code / Codex（已在运行中的 Agent 需重启生效）

🛡️ 前置条件、凭据隔离与合规风险边界

🔑 API 密钥与公众号凭据隔离（严防提交到 Git）
  • 配置位置：用户级放 ~/.baoyu-skills/.env，项目级放 <project>/.baoyu-skills/.env（环境变量加载优先级：命令行 > 系统环境 > 项目级 > 用户级）。
  • 防泄漏必做：使用项目级配置时，立刻把 .baoyu-skills/.env 写入 .gitignore，切勿把 WECHAT_APP_SECRET 或生图 API Key 推送到公开仓库。
  • 公众号 IP 白名单：官方 API 模式要求出口 IP 在微信公众号后台白名单内；家庭动态 IP 建议改用本机 Chrome 扫码模式，或配置基于 SSH 密钥的 remote-api 转发模式。
🚨 审慎对待 baoyu-danger-* 前缀技能（逆向非官方接口）
  • baoyu-danger-gemini-web 与 baoyu-danger-x-to-markdown 通过浏览器 Cookie 或逆向工程访问非官方接口，原仓在「免责声明」中已明确标注使用风险自负。
  • 上游页面或接口改动会随时导致失效；X 平台检测到非官方调用时可能触发账号风控或限制。
  • 合规建议：生图与内容采集优先走正规官方 API（如 baoyu-image-gen 配合国内通义万相/豆包或官方 OpenAI/Google Key），避免把主力账号 Cookie 暴露在自动化脚本中，并遵守各内容平台的原创与发布规范。

❓ 常见问题 FAQ

Q1：为什么大家强调不要一次全装这 22 个技能？

Agent 启动时会把已安装 Skill 的元信息注入上下文。22 个技能同时挂载既浪费每轮 token，也容易在「写文章」「画图」等相近口令上互相抢触发。按场景挑 2–4 个高频项单装，响应更准、成本更低。

Q2：发微信公众号文章，还需要单独装 baoyu-markdown-to-html 吗？

不需要。原仓说明 baoyu-post-to-wechat 已内置 Markdown 到公众号 HTML 的转换流程；只有当你习惯把转换后的 HTML 手动粘贴到其他编辑器，或者需要单独预览 HTML 时才值得装 baoyu-markdown-to-html。

Q3：没有固定公网 IP 进不了公众号白名单，还能用 baoyu-post-to-wechat 吗？

可以，有两种官方支持方案：一是改用 Chrome 浏览器模式（首次扫码登录后自动保留独立会话）；二是若你有一台固定 IP 云服务器，可启用 remote-api 模式，通过 SSH SOCKS5 仅转发 API 请求，排版与 AppSecret 都留在本地。

Q4：国内开发者没有海外信用卡，能用它的配图和画图功能吗？

可以。baoyu-image-gen 原生支持阿里通义万相（DASHSCOPE_API_KEY）、智谱 Z.AI、MiniMax、即梦（Jimeng）与豆包（ARK_API_KEY / Seedream）。如果画的是技术流程图或架构图，直接用 baoyu-diagram 生成纯 SVG，零额外 API 费用。

Q5：多个公众号怎么避免串号或配色混乱？

在 .baoyu-skills/baoyu-post-to-wechat/EXTEND.md 中配置 accounts 列表即可为每个公众号设置独立别名、作者、主题和发布方式；浏览器模式下每个账号还会使用独立的 Chrome 配置目录，登录态互不干扰。
