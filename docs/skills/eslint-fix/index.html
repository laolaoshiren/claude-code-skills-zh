⚖️ 交互式 ESLint 修复边界判断器

点击 4 种真实工程场景，查看 eslint-fix 在「预检锁定版本 → 限范围修复 → 复验通过」链路中的精确处理边界：

Stage 1
预检锁定版本
读 package.json、lockfile 与本地 lint script
Stage 2
限范围预览与修复
--fix-dry-run 确认范围，只改目标文件
Stage 3
复验通过与 Diff 核查
重跑目标 lint + 按风险跑类型检查或测试
✅ 允许限范围自动修复（需先 dry-run 预览）

格式类规则经只读基线与预览确认后，仅对目标文件执行 --fix

如 semi、quotes、indent、no-trailing-spaces、comma-dangle、arrow-parens、prefer-const 等常见可自动修复规则，先确认不与用户未提交改动重叠，再限定在指定文件范围内执行。

✅ 技能会执行 1) 用项目锁定包管理器跑只读基线并记录版本与 error/warning 数；2) 用 --fix-dry-run 预览预计改动；3) 仅对确认文件执行 --fix 并复跑 lint 与 git diff 检查。
🚫 明确禁止 不默认扫描或 --fix 整个大型仓库；不打乱项目原有的 Prettier 与 ESLint 执行顺序；不凭 dry-run 直接宣称已编译通过。

🧭 5 步安全修复工作流

1

识别项目工具链与版本锁

读取 package.json（scripts、devDependencies、packageManager）、npm/pnpm/Yarn/Bun lockfile，以及 eslint.config.*、.eslintrc.*、Prettier 与 TypeScript 配置。优先运行仓库已有 lint script。

2

建立只读基线

对用户指定或本轮改动范围执行只读检查，记录实际命令、ESLint 版本、退出状态、error/warning 数量与规则分布，区分基线已有问题和本轮引入问题。

3

预览可修复范围与冲突检查

使用 --fix-dry-run 或 JSON 输出评估改动，核对 git diff 是否与用户修改重叠，并将报错拆分为「可自动修复」「需理解语义」「需配置决策」三类。

4

限定范围精准修复

仅对已确认文件执行 --fix；遇到 no-explicit-any、未处理 Promise 或 React Hooks 依赖等语义规则时结合类型与调用方修改，绝不机械替换或默认关闭规则。

5

多维度复验与 Diff 收尾

重新运行目标范围 lint，按改动风险补跑类型检查、相关测试或构建；最后核对 git diff，确认无 lockfile、构建产物或无关格式变动，并记录未解决规则与原因。

🛡️ 三类规则分流与安全红线

问题类别 典型规则 / 表现 eslint-fix 处理方式
可自动修复类 semi、quotes、indent、no-trailing-spaces、comma-dangle、arrow-parens、prefer-const 经 --fix-dry-run 确认无大面积意外 diff 后，限定目标文件执行 --fix 并复验。
代码语义类 no-explicit-any、未处理 Promise、React Hooks 依赖告警 结合类型定义、调用方与运行路径手工修复，改完按风险运行类型检查与测试。
依赖与配置决策类 本地缺失 ESLint、.eslintrc.* 迁移至 eslint.config.*、Prettier 规则冲突 不擅自安装依赖、改 lockfile 或修改配置文件；先报告诊断结果，获明确授权后再变更。
🚫 绝不越过的 4 条工程底线
  • 不跑未锁定的裸 npx：避免联网拉取最新大版本导致配置不兼容或污染环境。
  • 不覆盖工作树已有修改：目标文件存在未提交重叠改动时，先向用户报告。
  • 不为消错关闭规则：不默认插入 eslint-disable、全局 ignore 或下调规则级别。
  • 不虚报验证状态：对应 lint、类型检查或构建命令必须真实运行并退出码为 0，才声称已修复。

❓ 常见问题 FAQ

为什么禁止在仓库里直接执行裸 npx eslint？

裸 npx 在本地未命中版本时可能直接从网络下载最新版 ESLint，容易与项目既有的 .eslintrc.*、插件版本或 Node 版本冲突。eslint-fix 只使用仓库已有 lint script 或已确认锁定安装的本地包管理器执行方式。

大型 Monorepo 跑一次会不会把几百个无关文件全格式化了？

不会。规则明确要求先对用户指定或本轮相关文件建立只读基线，并做 --fix-dry-run 预览；可能产生大面积格式 diff 或改动逻辑时必须先征得用户确认。

它能帮我把旧版 .eslintrc 迁移到 ESLint 9 flat config 吗？

可以诊断配置兼容问题并给出迁移方案，但修改 ESLint / Prettier 配置文件、升级依赖或改动 lockfile 属于高影响操作，技能会先汇报差异并等待你明确授权再执行。

Windows 和 macOS/Linux 上跑项目 lint 有什么区别？

eslint-fix 要求跨平台优先调用项目已有 npm/pnpm/Yarn/Bun scripts 与标准路径，不硬编码某个 shell 的专属语法，降低 Windows PowerShell 5.1 下的命令报错概率。
