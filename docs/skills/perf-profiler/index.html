🎛️ 交互式排查路线：遇到哪类慢问题，该采什么证据？

点击对应性能症状，查看 perf-profiler 要求的基线口径、必采证据与最小改动护栏：

慢接口 / CPU 热点排查

1. 基线口径

固定并发度、预热轮次、数据规模与代码提交 SHA，记录 P50/P95/P99 与波动范围。

2. 必采证据

CPU Profiler / 火焰图（pprof / py-spy / clinic / async-profiler）定位真实热点栈，排查同步阻塞与重复计算。

3. 复测与回滚

单点改动最重热点后按同条件复测，并先跑通正确性单测；严禁删校验换速度。

⚖️ 三级证据等级与生产安全红线

报告强制标注三级证据等级

  • 已测量：具备可复现基线、真实 profiling 产物与同条件前后对比数据；
  • 静态推断：由复杂度、循环嵌套或配置推导的候选点，尚未实测；
  • 待验证：缺环境、数据或权限，诚实说明当前无法定量判断影响。

绝对不越界的安全与诚实原则

  • 生产环境 EXPLAIN ANALYZE、压测、加索引或改连接池前必须明确授权；
  • 不在报告中暴露生产数据、凭据或含敏感信息的 profile 原始产物；
  • 绝不为了漂亮数字缩小测试数据规模、改变统计口径或删除校验逻辑。

❓ 常见问题 FAQ

支持哪些后端和前端技术栈？

语言无关，流程优先复用目标项目已安装的基准与分析工具（Go pprof、Node --cpu-prof、Python cProfile/py-spy、SQL EXPLAIN、Lighthouse/Bundle Analyzer）。

输出报告包含哪些关键字段？

固定交付：目标指标与场景、基线测量方法、带证据等级的发现表、改动与权衡说明、同条件复测结果、未控制变量以及回滚方式。
