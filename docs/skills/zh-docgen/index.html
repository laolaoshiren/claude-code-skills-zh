📌 必须核验的源码证据

路由注册文件（如 src/routes/orders.ts）、控制器签名、请求/响应 TypeScript 类型或 Pydantic Schema、真实错误处理分支与 JSDoc / docstring。

🚫 防编造与缺口处理红线

禁止凭路径名臆造分页参数、隐藏状态码或未在代码中实现的限流规则；线上网关超时、鉴权 Token 申请流程等源码未体现的信息，一律标为「待补充」。

### POST /api/v2/orders/refund

- **证据来源**：`src/routes/orders.ts:28`、`src/schemas/refund.ts:12`
- **请求体参数**：
  | 字段 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `orderId` | `string` | 是 | 订单主键（UUID 校验见 `refund.ts:14`） |
  | `refundNo` | `string` | 是 | 幂等退款单号，重复提交返回 `409` |
  | `reason` | `string` | 否 | 退款说明，最大 200 字符 |
- **真实错误码**：`400 INVALID_ORDER` / `409 DUPLICATE_REFUND`
- **待补充项**：线上网关单日退款限额需人工确认
交付汇总检查：已核对路由路径、Schema 字段与错误分支；未改动任何业务源码；目标文件存在时先输出 diff 摘要。

🧭 4 步证据驱动工作流（从源码盘点到安全交付）

1

盘点项目与明确文档目标

先确认文档类型（架构文档 / 模块说明 / API 参考 / 配置与运维手册）与目标路径（如 docs/architecture.md）；读取 package.json、pyproject.toml、go.mod、Cargo.toml、Makefile、已有 README.md 与 docs/，防止文档口径互相打架。

2

提取真实代码与配置事实

架构与模块追踪入口文件、分层依赖、数据存储与外部集成，只画真实组件的 Mermaid 图；API 参考直接从路由、控制器与类型定义提签名与错误路径；配置与命令仅来自 .env.example、配置加载代码和真实 scripts。

3

按需组织结构并预览确认

不硬塞无关章节，保留已有文档中的业务背景、历史决策记录和人工注意事项；若目标路径已存在文档，先展示待修改范围或 diff 摘要，取得用户确认后再执行落盘；仅要求起草时直接输出正文。

4

跨平台校验与结构化汇总

核对文档内相对链接、文件路径、真实命令与代码块语言标识，涉及终端命令时标注 macOS / Linux 与 Windows PowerShell 差异，统一 UTF-8 编码写入，最后输出包含「生成/更新文件、证据来源、已验证项、待补充项」的中文汇总。

🛡️ 核心原则与安全红线

✅ 4 条硬核编写准则
  • 证据驱动，零编造：每个模块名、配置项、环境变量、CLI 参数和 API 路径必须有仓库源码支撑；查不到的明确标「待补充」。
  • 保护人工沉淀内容：更新既有 docs/ 前先全文通读，保留团队踩坑记录和架构决策，禁止整篇覆盖重写。
  • 落盘先确认：默认先确认目标路径与是否覆盖已有文件，避免意外污染工作树。
  • 中英文表达规范：简体中文自然解释，文件名、配置键、命令和技术术语保持英文原样。
🚫 绝不越界的安全边界
  • 零凭据泄露：严禁将 .env、配置文件或测试数据里的真实 Token、密码、私有内网地址写入技术文档。
  • 不碰业务源码：不顺手修改任何业务代码，也不删除现有文档目录。
  • 不虚报验证结果：未实际执行过文档里的启动、测试或构建命令时，绝不声称命令已验证跑通。

❓ 常见问题 FAQ

zh-docgen 和 zh-readme、ds-mapper 有什么区别？

zh-docgen 专攻 docs/ 下的架构设计、模块开发指南、API 参考与配置运维手册；开源项目首页 README 编写交给 zh-readme；仅需快速生成带中文注释的目录树导览则交给 ds-mapper。

更新已有的 docs/ 文档时，会把我手写的业务背景删掉吗？

不会。技能规则要求更新既有文档前必须先完整阅读原文件，保留有效业务背景、架构决策记录和人工注意事项，并先展示待修改范围或 diff 摘要，经你确认后再写入。

源码里找不到某些线上运维参数时，它会自己编一个默认值吗？

严禁编造。所有环境变量、默认值、API 参数和错误码必须来自真实源码或 .env.example；源码未体现的信息会在文档及交付汇总的「待补充项」中明确列出，提醒人工补齐。

Windows 环境下生成的 Markdown 文档会出现中文乱码吗？

不会。技能明确要求写入文件统一采用 UTF-8 编码，并在运维/启动命令章节对 macOS / Linux 与 Windows PowerShell 差异做显式说明。
