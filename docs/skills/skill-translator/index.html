⚠️ 为什么直接让 AI 翻译英文 Skill 经常「翻完就坏」？

SKILL.md 不是普通英文文章，而是 Agent 运行时解析的结构化指令契约。直接把文件扔给模型说「帮我翻译成中文」，最常踩中 4 类隐性故障：

1. Frontmatter 与路由字段被误译

把 YAML 里的 name、allowed-tools、argument-hint 译成中文，或在描述里直接写未转义英文冒号 :，会导致插件市场或 Agent 根本无法解析该 Skill。

2. 代码块、CLI 参数与占位符被改写

把 --dry-run、$ARGUMENTS、{repo} 或相对路径 references/rules.md 误翻成中文后，Agent 照着执行命令直接报错。

3. 危险命令与 Windows 坑被原样带入

外部仓库里常见的 curl ... | sh、读取 ~/.ssh、或 Unix 专属的 find / sed -i / pbcopy、PowerShell 5.1 报错的 &&，普通翻译不会预警，落地才踩雷。

4. 丢掉触发词、安全门禁与原开源许可

机翻版常丢失英文专业术语触发词（导致中英文混问不命中），甚至顺手删掉原技能的确认门禁或原仓库 LICENSE 署名。

🧭 5 步完整工作流：先体检，再重写，最后 1:1 对账

skill-translator 把「汉化一个外部技能」拆成 5 个可审计的阶段，每一步都有明确的输入、产出与门禁：

1

结构盘点与不可翻译清单锁定

读取目标文件及其引用的同目录 references/、scripts/、templates/ 清单，动笔前先锁定四类禁止改写资产：YAML 键名与 name 值、fenced code block 内的代码与 CLI 参数、环境变量/模板占位符/报错原文、所有 URL 与相对路径，同时记录标题数、代码块数、表格数与门禁条数作为对账基线。

2

安全与 Windows / 跨平台预检表

逐段扫描源技能并输出分级风险表（仅预警附注，不私自篡改原技能核心逻辑）。检出高危信号时在报告顶部醒目提示并询问用户是否继续或剔除危险步骤。

3

Frontmatter 双语触发路由重构

保持 name 及其他技术字段不变，将 description 重写为四段式紧凑简体中文：核心能力 + 高频中文口语触发场景 + 保留关键英文术语触发词（如 PR review / migration / OpenAPI）+ 原有负向或安全边界；含冒号或特殊字符时自动用双引号安全包裹。

4

去机翻腔正文重写与保留原许可

消除「确保你总是优雅地…」等翻译腔；全部代码块与命令示例 100% 原样保留；Windows / 跨平台差异用 > 跨平台提示： 引用块补充等价写法；在无冲突前提下注入「默认中文汇报、改代码遵循目标仓库既有语言习惯」的轻量约定，并在文末保留 ## 来源与许可。

5

1:1 结构对账与覆写门禁

核对原文与译文的标题层级、代码块数、链接路径、安全门禁与占位符是否 1:1 一致。仅要求预览时不改磁盘；要求写入时优先落盘到新路径（如 SKILL.zh.md），覆盖原有英文文件前必须展示改动摘要并取得确认，写入统一采用 UTF-8（无 BOM）+ LF 换行。

以下以一个典型的英文测试/扫描 Skill 片段为例，展示 skill-translator 处理前后的差异：

改造前：原始英文 SKILL.md（痛点明显）

原始英文输入（片段） 
---
name: superpowers-tdd
description: Enforce strict TDD workflow before writing production code.
---

Run test discovery first:
```bash
find ./src -name "*.test.ts" && npm test -- --watch=false
```
Ensure you always gracefully refuse to skip failing tests.

中文提问「帮我按 TDD 写个单测」难以稳定触发；Windows 下直接运行 find 会撞系统自带 find.exe，PowerShell 5.1 也不支持 &&。

改造后：skill-translator 产出（契约零失真）

本地化输出 + 体检附注（片段） 
---
name: superpowers-tdd
description: "在编写生产代码前执行严格 TDD 红-绿-重构流程。用于中文提问要求先写测试再写实现、TDD 开发或补齐单测（test-driven / TDD）；未跑通红灯用例前不得跳过测试。"
---

先检索测试文件并执行一次非监听测试：
```bash
find ./src -name "*.test.ts" && npm test -- --watch=false
```
> 跨平台提示：Windows PowerShell 5.1 请改用 `Get-ChildItem -Path .\src -Recurse -Filter "*.test.ts"`，并将 `&&` 拆为两行执行。

发现失败用例时不得跳过，必须先修复或明确报告阻塞原因。

name、原代码块和 --watch=false 参数 100% 保留；触发描述兼顾中文口语与英文术语；Windows 踩坑点通过引用块透明提示，并附完整预检与对账报告。

📦 4 种零报错安装方式（含 Windows PowerShell 5.1+）

你可以随原创技能包一键安装，也可以只按需单装 skill-translator，避免给上下文增加额外负担。

方式 1：Claude Code 2.1+ 插件市场（最推荐）

整包 22 个原创

在 Claude Code 对话框中依次执行两条命令，自动注册并安装包含 skill-translator 在内的完整原创中文技能包。

Claude Code Slash Command 
/plugin marketplace add laolaoshiren/claude-code-skills-zh
/plugin install zh-skills@claude-code-skills-zh

方式 2：通用 CLI 按需单装（跨 Agent）

只装单个 Skill

只装 skill-translator 一个技能，适合 Claude Code、Codex、Cursor、Gemini CLI 用户（需要本机已装 Node.js）。

npx skills CLI 
npx skills add laolaoshiren/claude-code-skills-zh --skill skill-translator

方式 3：Windows PowerShell 5.1+ 手动单装

零 && 报错

逐行兼容 Windows 自带 PowerShell 5.1 与 PowerShell 7+，不使用 && 与 Unix cp -r。

Windows PowerShell 
git clone https://github.com/laolaoshiren/claude-code-skills-zh.git
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse -Force ".\claude-code-skills-zh\skills\skill-translator" "$HOME\.claude\skills\"

方式 4：macOS / Linux 终端手动单装

Bash / Zsh

克隆仓库后仅复制 skill-translator 目录到全局 ~/.claude/skills/（若用于 Codex，可改为 ~/.agents/skills/）。

macOS / Linux Shell 
git clone https://github.com/laolaoshiren/claude-code-skills-zh.git
mkdir -p ~/.claude/skills
cp -r claude-code-skills-zh/skills/skill-translator ~/.claude/skills/

🛡️ 触发边界、局限与安全红线

📌 明确分工：哪些需求不该交给 skill-translator
  • 业务代码国际化（i18n）：提取源码硬编码文本、生成多语言 JSON/YAML 资源包，请使用本仓原创 i18n-helper。
  • 终端报错排查：单条英文异常堆栈翻译与定位，请使用本仓原创 error-translator。
  • 从零写中文项目文档：基于代码库撰写项目文档或中文 README，请使用 zh-docgen 或 zh-readme。
🔒 安全边界与合规约定
  • 绝不自动执行被审查 Skill 的外部命令：静态体检期间不会替你运行任何 shell 脚本、包安装命令或网络请求。
  • 不删除原有安全确认门禁：不会为了「省事」去掉原技能的风险免责声明或二次确认步骤。
  • 尊重原作者与开源许可：文末保留原项目链接与 LICENSE（来源缺失时如实注明「来源未提供许可信息」），不把本地化版本包装成原创；静态预检仅覆盖显性模式，安装第三方未知仓库前仍需人工复核。

❓ 常见问题 FAQ

Q1：直接让 AI 帮我翻译英文 SKILL.md，和用 skill-translator 有什么区别？

普通翻译容易把 name、YAML 键名、CLI 参数或 $ARGUMENTS 占位符一起翻坏，导致技能无法路由或执行报错；同时不会排查暗藏的危险命令和 Windows 语法坑。skill-translator 强制执行「锁定保护清单 → 安全与跨平台预检 → 双语触发重构 → 去机翻重写 → 1:1 结构对账」，把翻译变成可核验的工程流程。

Q2：运行后会不会直接把原来的英文 SKILL.md 覆盖掉？

不会。只要求翻译/预览时，它直接输出报告与 Markdown 正文，不改动磁盘；要求写入文件时默认输出到新路径（如 SKILL.zh.md）。只有当你明确要求覆盖原文件，并在看完 diff 摘要后再次确认，它才会执行覆写。

Q3：它能审查带 scripts/ 脚本的第三方技能吗？会不会顺手跑起里面的脚本？

会一并盘点目标 SKILL.md 显式引用的同目录 references/、scripts/、templates/ 清单，并在静态审查中标出可疑网络请求或破坏性命令；但受安全边界约束，它绝不会自动执行被审查技能中的任何脚本或 shell 命令。

Q4：Windows 下使用经常遇到 GBK 乱码或 PowerShell 报错，skill-translator 怎么处理？

一方面，第 2 步预检会主动标出原文中不兼容 Windows 的命令（如 find、sed -i、/tmp、PowerShell 5.1 报错的 && 和 curl 别名），通过 > 跨平台提示： 给出等价写法；另一方面，第 5 步落盘时强制要求 UTF-8（无 BOM）+ LF 换行，避免 CP936/GBK 编码乱码。

Q5：除了 Claude Code，Codex、Cursor 或 Gemini CLI 能直接用吗？

可以。本技能本身是标准 SKILL.md，不仅能在这些 Agent 中运行，而且可以反向用来本地化团队的 AGENTS.md、CLAUDE.md、slash command 模板或 Cursor 规则文件。
