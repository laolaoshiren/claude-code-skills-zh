以 Lockfile 解析版本 + 官方 Advisory 为唯一依据

只调用项目锁定且当前环境已安装的只读审计命令，严禁裸跑 npx 或擅自下载工具；区分「依赖树中存在受影响版本」与「漏洞在当前程序中可达」，多工具结论冲突时并列呈现。

✅ 必查证据字段

  • Advisory ID、来源链接与含时区的查询时间
  • 实际解析版本、受影响范围与已知修复版本
  • 直接 / 传递依赖、生产 / 开发范围及 workspace 归属
  • 严重度来源、CVSS 版本与分数，及工具/代码路径可达性证据

🛡️ 硬性边界与防误报

  • 严禁裸跑 npx 或擅自执行 pip/go/cargo install 拉取审计工具
  • 工具缺失时如实记「未执行及原因」，绝不写成「未发现漏洞」
  • 不向未授权公共漏洞服务上传私有包名、Token 或私有 registry 凭据
  • 无发现时写「在本次工具与范围覆盖内未发现」并保留覆盖缺口

🧰 多生态首选证据与只读命令基线

存在多个互相冲突的 lockfile（例如仓库同时提交了 package-lock.json 与 pnpm-lock.yaml）时，先报告歧义再执行检查：

生态 首选证据基线 只读命令示例（仅当环境已安装时运行） 禁令与缺口处理
npm package-lock.json、项目 npm 版本 npm audit --json、npm outdated --json 不裸跑 npx，不默认跑 npm audit fix
pnpm pnpm-lock.yaml、packageManager pnpm audit --json、pnpm outdated --format json 区分 workspace 子包与生产/开发依赖
Yarn yarn.lock、项目 Yarn 版本 使用对应 Yarn 版本文档支持的只读 audit / outdated 命令 先确认 Classic v1 还是 Berry v2+ 语法
Python 虚拟环境、poetry.lock / uv.lock / Pipfile.lock pip-audit --format json；python -m pip list --outdated --format=json 未装 pip-audit 时记录未执行，不擅自 pip install
Go go.mod / go.sum govulncheck -json ./...；go list -m -json all 未装 govulncheck 时不擅自 go install
Rust Cargo.toml / Cargo.lock cargo audit --json 未装子命令时不擅自 cargo install
JVM / Ruby wrapper、pom.xml、Gradle、Gemfile.lock 优先运行仓库已有审计任务 严禁向构建文件临时注入第三方插件

🔒 发现、建议、执行三步分离

✅ 授权后安全升级流程

  • 确认允许修改的目录、包名、版本范围、包管理器与目标分支；工作树不干净时不覆盖用户原有改动；
  • 使用原生包管理器与精确版本执行最小升级，将直接/传递依赖与补丁/次版本/大版本分批处理；
  • 先读 changelog、迁移指南和运行时要求，每批修改后复验 lockfile diff、审计、测试、构建和 lint。

🚫 明确禁止的高风险捷径

  • 未经明确授权直接修改 manifest、lockfile、源码或 CI 配置；
  • 默认执行 npm audit fix、pip-audit --fix、--force 或一把梭大版本升级；
  • 凭“两年未更新”就推断有漏洞，或把 copyleft 许可证粗暴贴上“高危/传染”法律定性标签。
⚖️ 许可证审计合规声明

dep-auditor 仅整理包元数据、SPDX 标识、LICENSE 原文及例外条款，并结合你的分发方式、静态/动态链接、SaaS 使用、二次修改与双重许可列出待确认事项；需要正式法律意见时，必须交由公司法务或开源合规人员确认。

❓ 常见问题 FAQ

本地没装 pip-audit 或 cargo-audit 时，dep-auditor 会帮我自动下载安装吗？

绝对不会。dep-auditor 严禁为了完成审计而裸跑 npx，也禁止擅自执行 pip install、go install、cargo install 或向构建文件临时注入插件。工具缺失时会在报告「执行覆盖」里如实记录「未执行及原因」，再单独提供可选安装方案等待用户授权，绝不把工具缺失写成「未发现漏洞」。

dep-auditor 对 GPL / AGPL 许可证会直接判成高危吗？

不会。dep-auditor 明确坚持「只陈述许可证事实、不作法律结论」：不把 GPL、AGPL 或其他 copyleft 许可证统称为「传染性许可证」，也不固定映射到高/中/低风险，而是列出包元数据、SPDX 标识、LICENSE 与例外条款，并结合分发方式、SaaS 场景与双重许可整理待确认事项，建议由合规或法律人员作最终判断。

为什么一定要看 lockfile，只读 package.json 或 requirements.txt 不行吗？

manifest 中的版本范围（如 ^1.4.0）无法证明当前实际安装的精确版本，也看不到完整的传递依赖树。dep-auditor 优先从 package-lock.json、pnpm-lock.yaml、yarn.lock、poetry.lock、uv.lock、go.sum、Cargo.lock 等锁文件核实解析版本；缺失 lockfile 时会把覆盖缺口明确写入报告。

授权修复漏洞时，dep-auditor 会直接跑 npm audit fix --force 吗？

不会。dep-auditor 把「发现问题」「建议修复」「执行修改」严格分开，禁止默认运行 npm audit fix、pip-audit --fix、--force 或批量大版本升级。获得明确授权后，按直接/传递与补丁/次版本/大版本分批精准升级，并复验 diff、测试、构建与 lint。
