切换典型项目栈，直观查看 env-manager 如何只提变量名不回显真实值、拦截前端前缀泄露，并生成带格式约束的脱敏 .env.example：

📋 只读脱敏核查报告（零明文回显）

发现 2 项阻断风险
  • ✅ 已定义且已引用：APP_ENV（已设）、DATABASE_URL（已设，值已脱敏）
  • ❌ 代码已引用但模板缺失：SENDGRID_API_KEY（src/mail.ts）
  • 🚨 客户端前缀泄露风险：NEXT_PUBLIC_JWT_SECRET 会被打入浏览器 Bundle，须去除 NEXT_PUBLIC_ 前缀
  • 🔍 Git 跟踪核查：执行 git ls-files ".env*" 确认 .env.local 未被误提交进版本库

📄 生成的脱敏 .env.example（确认后写入）

零真实密钥 · 仅占位符 
# 应用基础配置
APP_ENV=development            # development | staging | production
NEXT_PUBLIC_API_BASE=https://api.example.com

# 数据库与认证（严禁加 NEXT_PUBLIC_ 前缀）
DATABASE_URL=                  # 必填，格式：postgresql://user:pass@host:5432/db
JWT_SECRET=                    # 必填，至少 32 位高熵随机字符串

# 邮件服务（补齐源码引用缺口）
SENDGRID_API_KEY=              # 必填，生产环境通过 Secrets 注入
🪟 Windows UTF-8 写入保护与确认门禁：生成或更新 .env.example / 校验 Schema（Zod / Pydantic Settings）前先展示 diff 并等待你确认；在 Windows 下由脚本读写含中文注释的文件时，强制显式声明 encoding="utf-8"，彻底规避 CP936/GBK 报错或乱码。

🚦 前端框架客户端公开前缀与 Docker 速查

大量密钥事故并非来自黑客入侵，而是开发者随手给后端密钥加了框架公开前缀，直接打进了浏览器 JS 产物或容器镜像层：

框架 / 运行时 客户端暴露前缀 / 危险指令 常见本地文件 安全边界说明
Next.js NEXT_PUBLIC_ .env.local 后端私密变量（数据库口令、JWT 密钥、支付私钥）严禁加此前缀
Vite VITE_ .env / .env.local 会在构建期静态替换进前端 Bundle，任何访客可见
Create React App REACT_APP_ .env 会打入前端构建产物，仅允许放公开配置
Nuxt NUXT_PUBLIC_ .env 属于运行时公开配置，服务端敏感项应放私有 runtimeConfig
Vue CLI VUE_APP_ .env 会打入前端构建产物，不可存放私有凭证
Docker ARG vs ENV compose.yml 勿把敏感密钥写入 ARG 导致明文留存在镜像构建历史层

🛡️ 安全核查清单与职责边界

✅ 6 项核心安全核查

  • 扫描与报告只展示变量名及脱敏状态，绝不回显真实 Secret；
  • 确认 .env 及含密钥本地文件已写入 .gitignore 且 git ls-files ".env*" 为空；
  • .env.example 与源码 process.env / import.meta.env / os.getenv / os.Getenv / env::var 同步；
  • 后端敏感变量未误加前端公开前缀，生产环境走 GitHub Secrets / Vault / 云 KMS；
  • 按需产出 Zod / Pydantic Settings / .env.schema.json 校验规则与 monorepo env_file 挂载方案。

🚫 严格修改边界与分工

  • 默认不自动删除或改写真实 .env；写入任何模板或 Schema 前必须先展示差异并获确认；
  • 静态扫描未发现引用的变量仅标「待人工确认候选」，严禁自动删除（可能由 CI/容器/框架隐式读取）；
  • 全仓库注入/越权漏洞审计 → 请转 security-audit；第三方依赖 CVE 核查 → 请转 dep-auditor。

❓ 常见问题 FAQ

让 env-manager 扫描本地 .env 文件，它会把我的真实 API Key 打印出来吗？

绝对不会。env-manager 严守「凭据零回显」红线：扫描 .env* 时只提取变量名、来源文件和是否为空，严禁在终端输出、校验报告、.env.example 或聊天记录中打印任何真实 API Key、Token 或密码原文。

静态扫描发现某些变量没在代码里引用，它会自动帮我删掉吗？

不会。很多环境变量是被 CI 流水线、Docker 容器、云平台或动态拼接代码隐式读取的。env-manager 会把这类变量标为「静态扫描未见引用（待人工确认候选）」，绝不自动删除，且任何写入 .env 或 .env.example 的动作都必须先展示差异并取得确认。

在 Windows 下生成带中文注释的 .env.example 为什么强调 UTF-8？

Windows 中文环境下 Python 等脚本默认可能采用 CP936/GBK 编码，直接读写带中文说明或 Emoji 的 .env / .env.example 容易触发 UnicodeDecodeError 或写入乱码。env-manager 要求脚本显式声明 encoding="utf-8"，保证跨平台无乱码。

前端框架里哪些环境变量前缀会暴露到浏览器？

Next.js 的 NEXT_PUBLIC_、Vite 的 VITE_、Create React App 的 REACT_APP_、Nuxt 的 NUXT_PUBLIC_ 和 Vue CLI 的 VUE_APP_ 都会进入客户端产物或运行时公开配置。数据库密码、JWT 密钥、支付私钥等后端敏感变量严禁加这些前缀，Docker 也不应把密钥写入 ARG 留在镜像层。
