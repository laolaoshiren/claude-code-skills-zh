ds-mapper：跨平台项目目录结构地图生成器

接手陌生仓库的第一步不是盲目翻文件，而是先拿一张真实的中文地图。ds-mapper 严格只读扫描代码库，自动绕开 Windows find.exe 报错与 node_modules 噪声，读取真实清单与入口文件后，输出带中文注释的 3 层 ASCII 目录树、模块职责对照表 与 启动入口建议。

🧭 4 步只读项目制图流程

1

跨平台只读扫描根目录

按优先级选用扫描方式：Agent 原生文件列举 → Git 仓库 git -c core.quotepath=false ls-files → 无 Git 的 Windows 用 PowerShell Get-ChildItem -Depth 3 → 无 Git 的 macOS/Linux 用 ls -la 或 find . -maxdepth 3。

2

读取真实清单文件，拒绝凭目录名瞎猜

读取实际存在的 package.json、pyproject.toml、Cargo.toml、go.mod、pom.xml 与 README.md，核实真实编程语言、Web 框架、包管理器和 Monorepo 工作区边界。

3

抽样阅读核心目录入口文件

进入核心业务目录抽样查看入口文件与典型模块，用一句自然简体中文概括该目录职责；没实际读到的目录绝不编造用途，明确标出「待进一步查看」。

4

交付 4 段式结构地图

固定输出「🔧 项目信息」「🌳 带中文注释的 ASCII 目录树」「🗺️ 模块职责对照表」「💡 启动/文档/配置入口建议」，让你 30 秒找到该从哪个文件开始读。

🛡️ 自动过滤清单与只读安全底线

🧹 自动跳过的噪声目录

扫描阶段自动过滤 node_modules、.git、vendor、__pycache__、dist、build、.next、target 等依赖与编译产物目录，防止目录树被数万个缓存文件撑爆上下文。

🔒 只读与实事求是原则

默认严格只读，绝不修改、创建或删除仓库里的任何文件；默认最多展开 3 层深度，Monorepo 按 packages/ 或 apps/ 分区展示；未实际读取的目录绝不脑补功能。

❓ 常见问题 FAQ

为什么 Windows 下不能用常见的 find . -maxdepth 3？

Windows 系统自带的 find.exe 是查找文本字符串的命令行工具，不支持 -maxdepth 参数，直接运行会立刻报错。ds-mapper 内置跨平台策略，在无 Git 的 Windows 环境下改用 PowerShell Get-ChildItem -Depth 3。

仓库包含大量中文文件名或中文子目录时，Git 输出会乱码吗？

不会。使用 Git 遍历时显式加上 -c core.quotepath=false，直接展示清晰中文路径而非八进制转义字符。

支持非 Git 的普通本地源码压缩包目录吗？

支持。无 Git 仓库时会自动回退到 Agent 原生文件列举，或按操作系统分别采用 PowerShell Get-ChildItem -Depth 3（Windows）与 ls -la / find . -maxdepth 3（macOS/Linux）。

可以把生成的结构地图进一步扩展成正式的 docs/ 文档吗？

非常适合串联使用：先用 ds-mapper 30 秒摸清全局目录边界与入口文件，再用 zh-docgen 针对重点模块生成详细的架构设计与 API 手册。
