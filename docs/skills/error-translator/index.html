🧪 交互式报错分类翻译示例

切换 3 类高频报错，预览 error-translator 如何同时做到「保留原报错文本 + 根因解释 + 最小修复」，并清晰标注技能分工：

TypeScript 5.x · 编译与类型错误 🔒 默认只读输出 · 保留原报错与标识符
TS2322: Type 'string | undefined' is not assignable to type 'string'. (src/order.ts:42:5)
🌐 自然中文翻译（术语保真） TS2322：不能将类型 string | undefined 赋值给期望为 string 的目标（位置：src/order.ts 第 42 行）。
🔍 触发根因 开启 strictNullChecks 后，调用方或字典取值返回了可能为 undefined 的可选值，直接传给只接收 string 的参数导致编译阶段拦截。
❌ 修改前（有问题的写法） 
const token: string = headers.get('x-trace-id');
✅ 修改后（最小安全修复） 
const traceId = headers.get('x-trace-id');
if (!traceId) {
  throw new Error('缺少 x-trace-id 请求头');
}
分工提示：此类单条编译类型错由 error-translator 直接解读；如果是 ESLint 规则批量告警与自动修复，请交给 eslint-fix。

🧭 4 步只读翻译与排障流程

1

识别语言、框架与运行平台

精准判定 Python、Node.js、TypeScript、Java、Go、Rust、C++、SQL 或 Windows PowerShell/GBK 平台差异，避免把平台命令问题误判为代码 Bug。

2

保留原文与标识符的自然翻译

按「原始消息 → 中文翻译」输出，完整保留错误码、类名、函数名、配置键与文件路径，不胡乱意译，方便你继续检索源码或上游 Issue。

3

结合堆栈业务帧定位根因

优先定位最内层业务代码帧并结合当前仓库真实行号分析直接诱因；遇到截断报错时列出最可能的 2–3 种原因，并说明还需补充哪几行代码，绝不硬猜。

4

提供分层最小修复与预防建议

输出 1–3 个具体安全的修改方案（标注推荐方案及适用前提）与修改前后代码对比；若涉及装依赖或改环境配置，先说明影响并交由用户决定是否执行。

🛡️ 安全原则与 4 个相邻技能分工

实际场景 对应技能 职责界定
单条/短段英文报错、编译失败、Traceback、终端坑 error-translator 只读翻译、术语保真、堆栈根因定位与最小修复代码对比。
ESLint 规则报错诊断与限定范围修复 eslint-fix 锁定项目本地 ESLint 版本，先只读基线与 dry-run 预览，再限定范围修复并复验。
多行或大体积 .log / Docker / K8s 日志聚类排查 log-analyzer 大文件流式采样、UTF-16LE/GBK 识别、高频异常聚类与 traceId 因果链定位。
汉化海外英文 SKILL.md 或 AGENTS.md 规则 skill-translator 保留代码与前置命令无损本地化技能定义并做安全预检。
🔒 四项默认安全承诺
  • 默认只读不改文件：未得到你明确修改指令前，只做解释与方案对比。
  • 敏感凭据脱敏：对粘贴报错里的 Token、Cookie、数据库连接串和密码自动遮蔽。
  • 缺上下文不硬猜：堆栈被截断时明确列出待补充的代码片段，不编造不存在的根因。
  • 高影响命令先告知：涉及安装依赖、升级运行时或改环境配置时先说明影响由你决策。

❓ 常见问题 FAQ

它支持哪些编程语言和常见框架报错？

覆盖 Python（TypeError、ModuleNotFoundError、UnicodeDecodeError、asyncio）、JS/TS（ESM/CJS 混用、React Hooks、类型收窄）、Java、Go、Rust（borrow checker / lifetime）、SQL 以及 Windows PowerShell 常见终端坑。

和直接把报错扔给大模型问“这是啥意思”有什么不同？

普通问答经常过度意译丢掉关键报错原文、脱离你仓库里的真实代码瞎猜，或者一上来就擅自修改文件和装包。error-translator 强制术语保真、默认只读、脱敏凭据，并优先结合仓库真实文件行号给出修改前后最小对比。

如果报错信息只有半截，它会不会瞎编一个答案？

不会。规则明确要求「缺上下文不硬猜」：会列出最可能的 2–3 种原因，并清楚告诉你还需要补充哪几行源码或完整 traceback。

我要排查整个 50MB 的日志文件里为什么 502，应该用它吗？

大体积或多行日志聚合请交给 log-analyzer；等它把源头异常行抽出来后，如果需要深入解释具体语言堆栈与代码改法，再衔接 error-translator。
