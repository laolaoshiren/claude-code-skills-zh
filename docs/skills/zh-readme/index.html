🧭 5 步取证工作流与交付前自检清单

1

读取真实仓库资产

优先检查 package.json、pyproject.toml、Makefile、Cargo.toml、go.mod、LICENSE 与入口代码，绝不凭仓库名猜功能。

2

打磨 30 秒首屏四件套

首屏清晰回答「解决什么问题、适合谁用、30 秒怎么装、在线演示/官网在哪」，GitHub 原生地址优先，国内镜像仅作访问困难补充。

3

核验跨平台命令与数据口径

确保 Windows PowerShell 不出现 && 或裸 cp -r 陷阱；官网、徽章、版本号与数量口径全仓统一不打架。

4

保护已有内容，确认后再覆写

仓库已有 README.md 时，先列出保留项与改动摘要，取得维护者确认后再以 UTF-8 落盘，信息不足处标「待补充」绝不编造。

⚡ 4 种安装方式

git clone https://github.com/laolaoshiren/claude-code-skills-zh.git

cp -r claude-code-skills-zh/skills/zh-readme/* ~/.claude/skills/zh-readme/

❓ 常见问题 FAQ

适合拿来重写老开源项目的 README 吗？

非常适合。它会先盘点原 README 里的徽章、鸣谢与有效说明，只重构首屏价值主张、补齐真实安装命令和结构导航，不会粗暴清空你的历史积累。

和 zh-docgen 怎么区分？

zh-readme 专注根目录门面首页与上手转化；如果要生成 docs/ 下的模块架构手册或 API 参考文档，使用 zh-docgen。
