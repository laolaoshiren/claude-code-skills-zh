refactor-advisor：存量代码坏味道诊断与分阶段重构顾问

老项目动一处牵全身，最怕 AI 一上来就“帮你全部重写”。refactor-advisor 默认严格只读：扫描真实行数、嵌套层数、引用面与高频变更热点，先查测试护栏缺口，按红/黄/绿严重度输出 Before / After 示意 与 P1–P3 小步可验证路线图，绝不拍脑袋估工时，也绝不私改源码。

🔴 高优先 · 高风险/高收益 复杂度：中 · 阶段：P2 拆分热点 src/services/user.ts:45-120
单函数混杂入参校验、权限判断与数据库持久化（76 行，7 处调用）
可观测证据：函数长度 76 行、承担 3 段独立职责，近 30 次 Git 提交中被修改 6 次，属于高变动热点；当前仅主路径有集成测试，边界错误分支无单测。
Before（现状示意 · 只读分析未改动）
function processUser(data) {
  if (data) {
    if (data.email && data.role) {
      // 混杂校验、默认值补齐与写库逻辑
      return db.users.save(data);
    }
  }
  throw new Error('invalid');
}
After（推荐手法：Extract Function）
function processUser(data) {
  const validated = validateUserData(data);
  return saveToDatabase(validated);
}
🧪 前置护栏要求（P1 先行）：在拆分前先为 validateUserData 的空字段与非法角色分支补齐最小回归单测（可配合 test-generator）；重构全程保持抛错类型与返回值行为等价。

🧭 3 步只读诊断流程与 P1–P3 执行路线图

1

只读扫描真实可观测指标

优先使用当前 Agent 原生搜索与读取工具（或 rg），不硬编码仅限 Unix 的命令；统计文件行数、超长函数、参数数量、深层嵌套与重复业务分支，并借助 git -c core.quotepath=false log --name-only -n 30 --pretty=format: 识别高变动热点文件。

2

核查测试护栏、调用面与工作树保护

盘点目标模块的上下游引用位置与自动化测试覆盖情况，识别用户工作树中已有的未提交修改（严禁在后续授权重构中覆盖或混入无关改动）。

3

按「变更频率 × 影响面」排定 P1 / P2 / P3 路线图

先补齐核心模块回归测试（P1，低风险不改业务行为），再拆分 🔴 高优先核心热点（P2，全量单测 + 类型检查），最后清理 🟡 / 🟢 结构债务（P3，lint + 单测）；每步小步验证，未实跑测试绝不宣称无回归。

📋 8 类常见坏味道与推荐重构手法

坏味道 典型特征 推荐重构手法 严重度
长方法 单函数承担多段独立职责且过长 提取函数 (Extract Function) 🔴 高
上帝类 / 大文件 单个类或模块聚合过多无关联职责 按内聚边界拆分模块 / 提取类 🔴 高
重复业务逻辑 同一业务校验或转换逻辑散落多处 提取共享纯函数或领域服务 🔴 高
全局可变状态 模块级可变单例被多处隐式读写 显式传参或依赖注入 🔴 高
过长参数列表 多个强关联参数反复透传 引入具名配置 / 参数对象 🟡 中
嵌套过深 条件或循环嵌套达到 3+ 层 卫语句 (Guard Clause) 提前返回 🟡 中
过度耦合 业务层直接绑定具体基础设施实现 抽象接口边界 / 依赖反转 🟡 中
魔法数字与隐晦条件 无语义字面量或复杂布尔表达式 提取命名常量与谓词函数 🟢 轻微
⚠️ 行为等价与安全执行边界

重构严格遵循 Behavior-preserving（外部可观察行为不变）：若在分析中顺带发现产品逻辑 Bug，先单独报告而不悄悄混入重构；未经用户选定阶段并授权，严禁改写任何源码；经授权实施后每步必须实际运行项目测试、类型检查与 lint。

❓ 常见问题 FAQ

刚装上让它“分析 src/order 模块的技术债”，它会直接改代码吗？

不会。默认严格只读出方案，只有在你看完报告并明确指定“按 P2 方案实施第 1 项重构”后，才会小步修改并运行验证。

项目目前完全没有单元测试，它还敢拆核心模块吗？

不会盲目拆分。工作流第 2 步就会检查测试护栏，缺失测试的高风险模块会在路线图 P1 阶段优先列出「补齐最小回归测试」作为前置步骤（可配合 test-generator）。

工作区里我有还没提交的业务代码，授权重构时会覆盖掉吗？

不会。第 2 步专门要求识别工作树中用户已有的未提交修改，严禁覆盖或混入无关改动。

适合前端 React / Vue、Python、Go、Java 等不同技术栈吗？

适合。技能不绑定单一语言，优先使用当前 Agent 原生文件检索和跨平台 Git 命令，按目标仓库真实测试、类型检查与 lint 工具链制定验证方案。
