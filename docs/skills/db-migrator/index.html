🔎 交互式 ORM 迁移安全检查器

选择你项目使用的迁移框架，查看 db-migrator 如何探测工具链、先生成只读审查迁移，以及执行前必须核验的回滚与锁表护栏：

Prisma（Node.js / TypeScript）安全迁移流程

特征文件：prisma/schema.prisma · prisma/migrations/
1. 只生成供审查（不改库）

优先使用 --create-only 仅生成 SQL 迁移文件，人工检查生成的 DDL、索引语句与字段约束，严禁直接用 prisma db push 绕过迁移历史。

2. 回滚与锁表核验

Prisma 默认不自动生成 down.sql，需额外编写可审查的逆向 SQL 或快照恢复预案；大表加唯一索引或改类型须评估在线 DDL 方案。

3. 授权执行门禁

先在隔离本地/staging 核验升级与回滚路径，确认 DATABASE_URL 指向、数据备份与维护窗口后，开发用 migrate dev，生产/测试用 migrate deploy。

# 默认仅生成 SQL 供审查（不直接修改数据库） npx prisma migrate dev --name add-email-to-users --create-only # 审查 SQL 并经用户确认目标环境与备份后再执行： # npx prisma migrate deploy

🧭 4 步零事故迁移流程与回滚策略速查

1

识别迁移框架与数据库方言

读取项目配置与历史目录（Alembic、Django、Prisma、Drizzle、TypeORM、Flyway/Liquibase、Go goose/golang-migrate、Rails ActiveRecord），严格沿用既有版本号与命名规范，不猜测 MySQL / PostgreSQL / SQLite 方言。

2

对比 Schema 变更与检索业务源码

逐项识别表、列、默认值、非空约束、索引与外键差异；凡涉及重命名或删除列/表，先全文检索源码确认是否还有旧字段读写，避免灰度发布窗口期旧版本实例崩溃。

3

生成 UTF-8 迁移与回滚脚本

显式以 UTF-8 编码写入脚本（防 Windows CP936 写坏中文注释）；框架支持 downgrade / down.sql 时同步生成逆向逻辑，破坏性变更则明确写出快照恢复或前向修复方案。

4

大表锁表与向后兼容性风险评估

检查 MySQL ALGORITHM=INPLACE/INSTANT、gh-ost / pt-online-schema-change、PostgreSQL 非事务块 CREATE INDEX CONCURRENTLY，以及将新增非空列拆分为「可空 → 分批回填 → 加 NOT NULL」、将大批量数据回填与 DDL 分离执行。

📋 回滚策略速查表

变更场景 推荐回滚与演进策略 风险等级
新增列 / 新增表 确认无新业务数据依赖后，直接 DROP 新增列或表 可逆低风险
删除列 / 删除表 无法仅靠 DDL 找回已删数据；必须先备份，并优先采用 Expand & Contract 多阶段废弃 不可逆高危
修改列类型 / 缩窄长度 存在截断或精度丢失风险，需先抽样核验存量数据并保留备份 数据损失风险
大表加索引 / 改表结构 使用在线 DDL 或非阻塞建索引语法（如 PG CONCURRENTLY），提前确认维护窗口 锁表阻塞风险

⚖️ 触发边界与数据安全红线

适用场景与必须前置核对项

  • 适用：对比模型与 Schema 变更、生成各主流框架迁移/回滚脚本、评估大表锁表与灰度兼容性；
  • 执行前必须确认四要素：目标环境、连接串指向、数据备份状态、维护窗口；
  • 先在隔离本地或 staging 完整验证升级与回滚路径，再应用到生产库。

不适用场景与严禁越界行为

  • 不适用：慢 SQL 索引性能剖析 → perf-profiler；源码 SQL 注入安全审计 → security-audit；
  • 严禁在未获明确确认时直接执行 migrate、db push 或手工 DDL；
  • 严禁在迁移脚本或报告中硬编码真实数据库密码/连接凭据，也不得假设迁移可脱离版本元数据表重复执行。

❓ 常见问题 FAQ

使用 db-migrator 时会自动连接数据库执行 migrate 或 db push 吗？

不会。技能默认只负责识别框架、比对 Schema、生成迁移/回滚文件与风险报告；未经你明确确认目标环境、连接串指向、备份和维护窗口，绝不执行写库命令。

大表加索引、加非空列或删列时，db-migrator 如何规避锁表和线上报错？

按数据库方言提示非阻塞 DDL（PostgreSQL CREATE INDEX CONCURRENTLY、MySQL ALGORITHM=INPLACE/INSTANT 或 gh-ost），将新增非空列拆步回填，并在删列前检索代码旧引用提供 Expand & Contract 分阶段废弃方案。

为什么特别强调显式使用 UTF-8 编码写入迁移脚本？

Windows 默认控制台/文件编码常见为 CP936/GBK，未显式指定 UTF-8 写入中文注释会导致在 Linux CI 或数据库客户端中乱码甚至报错。

db-migrator 与 perf-profiler 的职责边界怎么区分？

db-migrator 负责表结构变更、迁移回滚与锁表风险审查；若要定位慢查询、N+1 SQL 或基于 EXPLAIN 做基线复测优化，请直接使用 perf-profiler。
