# 中文 README 生成器

## 触发边界

- **适用**：从零编写或重写优化开源项目 / 内部仓库的首页 `README.md`，提升 30 秒价值理解与上手转化。
- **不适用**：编写 `docs/` 下的深度架构设计或完整 API 参考手册 → `zh-docgen`；只输出目录结构地图 → `ds-mapper`。

## 核心原则

1. 先读代码、入口文件、包管理配置和已有文档，再写 README；不要只凭项目名猜功能。
2. 面向中文开发者表达，技术名词保留英文，解释用自然中文，避免“强大、优雅、革命性、现代化”等空泛宣传词。
3. 首页要解决三个问题：这是什么、为什么值得用、怎么在 30 秒内装上并跑起来。
4. 优先给出真实命令、真实路径、真实示例；涉及终端安装命令时兼顾 macOS/Linux 与 Windows（PowerShell 避免 `&&` 和裸 `cp -r` 陷阱）。
5. 如果项目已有 `README.md`，先保留有效信息、徽章与人工说明，补全缺失结构；**覆写已有文件前先展示变更摘要并取得用户确认**。
6. 如果项目包含官网、文档站、Issue 模板或镜像入口，保持单一正式入口与统一数据口径（Star、数量、版本号等不互相打架）。
7. 不编造未验证的性能数据、用户案例、兼容工具或官方身份；信息不足处显式标注「待补充」。

## 首屏优化模板

- **一句话价值主张**：明确解决什么问题与目标场景。
- **适合谁用**：点名典型人群或真实痛点场景。
- **最短安装方式**：提供可直接复制的命令，GitHub 原生地址优先，国内镜像仅作访问困难时的补充。
- **统一入口与社交证明**：适度呈现徽章、官网或代表性能力示例，不堆砌营销口号。

## 工作流程

1. 检查项目目录、包管理文件（`package.json`、`pyproject.toml`、`Makefile`、`Cargo.toml`、`go.mod`）、`LICENSE`、入口文件、测试目录和已有 `README.md`。
2. 提炼项目定位：解决什么问题、目标用户、核心能力与适用边界/限制。
3. 提取真实可复制的安装、运行与测试命令；若目标受众包含 Windows 开发者，确保不写仅限 Bash 却未标注平台的命令。
4. 起草或修订 README；若仓库已有 `README.md`，先列出保留项与改动摘要，经确认后再落盘，写入时使用 UTF-8 编码。
5. 对照自检清单完成核验，并报告未核实或需维护者人工补齐的占位内容。

## 自检清单

- [ ] 是否在 30 秒内说清“是什么、适合谁、怎么装”？
- [ ] 所有命令、路径、依赖、许可证是否来自真实仓库证据？
- [ ] 是否避免了 AI 腔、翻译腔和空泛形容词？
- [ ] 写入前是否已保护现有有效内容且未泄露敏感信息或本地私有路径？
- [ ] 跨平台（Windows / macOS / Linux）命令与链接是否准确可用？
