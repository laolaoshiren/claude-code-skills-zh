# 中文技术文档生成器

## 触发边界

**适用场景：**

- 为已有代码库生成或补全 `docs/` 下的架构设计文档、模块开发指南、配置参考、部署/运维手册或 API 参考文档。
- 将分散在源码注释（JSDoc / docstring / GoDoc）、路由定义与配置文件中的事实整理为结构化中文文档。

**不适用场景：**

- 撰写或重写开源项目首页 `README.md` → 请使用 `zh-readme`。
- 仅生成带中文注释的目录树速览 → 请使用 `ds-mapper`。
- 汉化第三方英文 `SKILL.md` / `AGENTS.md` → 请使用 `skill-translator`。

## 核心原则

1. **证据驱动，零编造。** 文档中的每个模块名、配置项、环境变量、CLI 参数、API 路径与命令必须来自仓库真实文件；无法证实的信息明确标为「待补充」，严禁凭项目名猜测。
2. **保护人工沉淀内容。** 更新已有文档前先完整阅读原文件，保留有效业务背景、决策记录和人工注意事项，不粗暴覆盖。
3. **落盘先确认。** 默认先确认目标文档路径、文档类型与是否覆盖已有文件，再执行写入；用户仅要求起草时直接输出正文。
4. **中文自然、术语准确。** 使用简体中文解释，技术术语、文件名、配置键和代码保持英文原样，写入文件统一采用 UTF-8 编码（兼顾 Windows 环境）。

## 工作流程

### 1. 盘点项目与明确文档目标

- 确认目标文档类型（架构文档 / 模块说明 / API 参考 / 配置与运维手册）及写入路径（如 `docs/architecture.md`）。
- 读取项目元信息（`package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml`、`Makefile` 等）、已有 `README.md` 与 `docs/` 目录，避免与现有文档重复或口径冲突。

### 2. 提取真实代码事实

- **架构与模块**：追踪入口文件、核心服务分层、依赖流向、数据存储与外部集成，绘制基于真实模块关系的 Mermaid 架构图（不画不存在的组件）。
- **API / 函数参考**：直接从路由注册、控制器、类型定义、Schema 或源码注释提取签名、必填/可选参数、返回值与真实错误路径。
- **配置与运行步骤**：仅从 `.env.example`、配置加载代码和真实 scripts 中提取启动、测试、构建命令与环境变量说明。

### 3. 组织文档结构与预览确认

按目标文档类型选用精简清晰的结构（不硬塞无关章节）：

- **项目/模块概述**：定位、核心边界、技术栈与真实模块关系图（Mermaid）。
- **环境与配置**：前置条件、环境变量表（字段名、是否必填、默认值、说明，严禁写入真实密钥）。
- **核心流程或 API 参考**：入参/出参表、可复制的真实调用示例。
- **常见排障与限制**：仅基于代码中真实存在的错误处理、约束或已知限制整理。

若目标路径已存在文档，先展示待修改范围或 diff 摘要，取得用户确认后再写入。

### 4. 校验与交付

- 核对文档中的内部相对链接、文件路径、命令与代码块语言标识均真实有效。
- 涉及跨平台命令时，注明 macOS / Linux 与 Windows PowerShell 的差异。

## 输出格式

写入或输出 Markdown 文档后，用简短中文汇总：

```markdown
## 文档生成汇总

- **生成 / 更新文件**：{路径列表，或「仅预览未落盘」}
- **证据来源**：{依据的核心源码与配置文件}
- **已验证项**：{路径引用、命令核对等}
- **待补充项**：{源码中未体现、需人工补齐的业务背景或线上配置}
```

## 安全边界

- 不把 `.env`、配置文件或测试数据中的真实 Token、密码、内网地址写入技术文档。
- 不修改任何业务源码或删除现有文档目录。
- 未实际执行文档里的运行/构建命令时，不声称已验证跑通。
